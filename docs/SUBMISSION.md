## 三、作品简介

### 150 字版

> 学术galgame Agent 是一款**学习优先**的开源 AI 教学游戏。模型扮演「鲸鱼娘」老师，用**苏格拉底式提问**带学习者自己发现答案——答不上来就降难度给提示，绝不直接讲解。每次判定都会写进游戏数值：学科熟练度、好感度、HP，达标后解锁「领主求助 → 魔将 → 学科魔王」的考试剧情。它支持 **BYOK 自带密钥**：每个人用自己的大模型接口（任何 OpenAI 兼容服务）与 ima 知识库，学自己的资料。零第三方依赖，`node src/server/server.js` 即可运行。

### 300 字版

> **学术galgame Agent** 是一款**学习优先**的开源 AI 教学游戏，把「AI 家教」做成了 galgame。
>
> 模型扮演「鲸鱼娘」老师，遵循一套**苏格拉底式提问框架**：六类提问（澄清 / 探询假设 / 探询依据 / 质疑视角 / 探询推论 / 质疑问题本身）、五种追问策略（漏斗 / 镜像 / 反事实 / 类比 / 策略性沉默）。它**不直接给答案**，而是逐层追问；答不上来就降难度给 1~2 档提示，答错则记入近期重点。
>
> 每次判定都真实写入游戏状态：学科熟练度、好感度、HP，并驱动「领主求助 → 魔将 → 学科魔王 → 魔神」的战斗剧情线。全科魔王通关即为「研究生」，最终挑战无限血条的魔神。
>
> 它还解决了 AI 教学产品的两个真问题：**① 密钥与隐私** —— BYOK 架构，凭证只存用户浏览器、随请求头发送，服务端不存储任何 Key；**② 学什么** —— 课程表由用户自己的 ima 知识库一键生成，也可直接拖入 `.md` / `.docx` 教材。
>
> 零第三方依赖（仅用 Node 内置模块），自带 12 项离线自测，并附完整的 Trae 项目规则与技能。

## 四、核心亮点

### 1. 苏格拉底式提问，而不是问答机器人
内置可复用的提问框架（**6 类提问 + 5 种策略 + 3 档追问梯子**），并沉淀为 **Trae 项目技能** `.trae/skills/socratic-questioning/`。项目规则明确要求：涉及教学方式的改动必须先加载该技能——**方法本身是被工程化管理的**，不靠临场发挥。

### 2. BYOK 自带密钥 —— 每个人学自己的资料
服务端**不存储也不需要**任何密钥。用户在页面「⚙ 设置」里填自己的**大模型接口**（任何 OpenAI 兼容服务，如 DeepSeek / 火山方舟）与 **ima** 凭证，凭证只存在浏览器 localStorage，随每次请求经 HTTP 头传递，用完即弃。因此公开部署时站点主不承担任何额度，也不存在密钥泄露面。

### 3. 课程表由你的 ima 知识库生成
点「拉取知识库列表」→ 每个知识库右侧「**+ 添加为学科**」→ 该知识库立刻成为一门可学学科并自动绑定。**你 ima 里有什么，游戏里就能学什么**；学科可增删、可换绑。没有 ima 也行：直接拖入 `.md` / `.txt` / `.docx` 教材（`.pdf` 实验性支持）。

### 4. 真的会「学」：熟练度 / 判定 / BOSS 战
不是套壳聊天。每次教学判定都会结算为数值：独立答对 `+12~15` 熟练度、提示后答对 `+6~9`、答错扣血并记入近期重点；达标后解锁领主（60）→ 魔将（75）→ 学科魔王（90）的考试剧情，并有濒死营救、败北特训、重试难度递增。

### 5. 零依赖、Trae 原生就绪
仅用 Node 内置模块，`git clone` 后一条命令即可运行，无 `npm install`。仓库自带 **Trae 项目规则**（`.trae/rules/`：技术栈约束、数值真源、提交信息规范）、**项目技能**（`.trae/skills/`）与 `AGENTS.md`，导入 Trae 即可让 AI 按项目约定协作开发。

## 六、WorkBuddy 技能版（腾讯 AI 办公智能体）

**WorkBuddy** 用的是技能（Skill）系统 —— 技能就是一个目录，装在 `~/.workbuddy/skills/`。
本仓库的 [`workbuddy/`](../workbuddy/) 目录是**可安装的技能包**，装完就能用。

### 装什么

| 技能 | 作用 |
|---|---|
| `academic-galgame` | 主技能：鲸鱼娘老师的教学流程 + 游戏状态 CLI + 内嵌引擎 + ima 接入 + 动画面板 |
| `socratic-questioning` | 提问框架：六类提问 + 五种策略 + 验证清单 |

安装：

```powershell
cd workbuddy; .\install.ps1          # Windows
```
```bash
cd workbuddy && chmod +x install.sh && ./install.sh   # macOS / Linux
```

### 只连两样东西

| 连接 | 是否必填 | 说明 |
|---|---|---|
| **① ima 知识库 API** | **必填** | 出题唯一的真实依据来源（技能包**不含内置语料**）。到 [ima.qq.com](https://ima.qq.com) → 开放平台 / API 拿 **API Key + Client ID** |
| **② LLM** | **二选一 / 可不填** | **不填** = 用 **WorkBuddy 自己的积分**（默认）；**填了** = 技能自己调一个 OpenAI 兼容 API（DeepSeek / 火山方舟 / Kimi / 智谱 / 通义 / 硅基流动 / OpenAI，内置 8 个预设 + 自定义） |

本地教材（`materials add`）是**可选加料**，不替代 ima。

### 它真的会读你的书

ima 自己的接口有两个硬限制（实测）：

- `search_knowledge` **只匹配书名，不搜正文**（`highlight_content` 恒为空）——
  查「睡眠」能命中《斯坦福高效睡眠法》，但查「复利」「注意力」一律 0 条，哪怕书里到处都是；
- `get_media_info` 给的是 **PDF/EPUB 原始文件**的下载地址 —— 当文本读只会得到
  `%PDF-1.6 %äüöß...` 这种乱码。

所以技能包自己做了一整套：**列文件 → 下载 → 抽正文 → 存本机 → 本地全文检索**
（`scripts/textract.js` + `ima_index.js`，纯 Node 零依赖，PDF 支持中文字体的 ToUnicode CMap）。

- 实测：10 个文件的知识库，34 秒解析 6 本 = **131.7 万字**；之后检索 **0.0 秒**
- **扫描版 PDF / 图片版 EPUB 会逐本列出书名和原因**，不会假装读过
- 这个能力在 **Node 版 / Python 版 / WorkBuddy 技能版三处行为一致**，
  同一个文件抽出的正文**逐字节相同**（`node scripts/check-textract.js <目录>` 可复验）

### 动画面板（不只是文字）

WorkBuddy 是对话式 Agent，但 galgame 的手感需要看得见。面板与 CLI **共用同一份存档**：

```bash
node ~/.workbuddy/skills/academic-galgame/scripts/galgame.js panel --port 8790
# 打开 http://127.0.0.1:8790
```

三个视图：

| 视图 | 内容 |
|---|---|
| **学科** | 立绘逐帧动画、HP / 好感条、学科熟练度与任务链、近期记录（新条目淡入） |
| **回合回放** | ⏮ 上一步 播放 下一步 ⏭ —— 逐步重现**每一轮结束时**的熟练度与好感 |
| **学习报告** | 教学轮次、判定正确率、净增熟练度、各学科明细、需要巩固的点 |

> 回放不是装饰：每轮结算时引擎会记下**实际生效**的增量（已考虑数值上下限的夹取），
> 所以能反推出每一轮结束时的真实数值。仓库里有回归测试
> `node scripts/check-panel-replay.js` 守着这条不变量 —— 回放末值必须等于当前状态。

## 十、可能被问到的问题（应答口径）

**Q：和直接和 ChatGPT 聊学习有什么区别？**
A：两点。一是**方法被工程化**：提问框架写成了 Trae 技能，项目规则强制教学习改动必须遵循它，不是靠临场发挥；二是**有学习闭环**：每次判定都结算为熟练度、驱动间隔复习与考试剧情，还会把答错的知识点记入近期重点——聊天窗口没有这些。

**Q：为什么是 galgame？会不会本末倒置？**
A：设计上明确「**学习优先，游戏只是外衣**」：题目要真难、答错有代价、掌握可量化。游戏化的作用是提供**持续动机**（熟练度可视化、BOSS 战、好感度），而不是降低难度。

**Q：BYOK 是不是把麻烦推给用户？**
A：是取舍。它换来的是：站点主不必为额度负责、公开部署无密钥泄露面、用户的数据只流向自己配置的服务。而且**不填任何 Key 也能完整试玩**（DEMO 模式），门槛并不高。

**Q：为什么零依赖？**
A：降低上手与审计成本——`git clone` 就能跑；同时让 Trae 里的 AI 能读懂全部代码（无需理解第三方库），这也是把它做成「Trae 友好项目」的前提。

**Q：苏格拉底式提问的效果怎么验证？**
A：框架本身有明确的判定结构（三档：独立答对 / 提示后答对 / 答错），每次判定都会落库成可观测的数值与近期记录，可在界面上直接看到「老师是否真的在追问而不是给答案」。

---

## 十一、一句话总结（用于收尾）

> 它不是在聊天窗口里加了个「老师」人设，而是把**一套提问方法论**工程化成了带数值反馈的学习系统 —— 而且让每个人都能接上自己的模型与自己的知识库。
